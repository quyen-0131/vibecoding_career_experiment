# An experiment is shaped by the role, not by the User's evidence gaps

A Career Experiment reproduces the real work of the job title the User picked
— the kinds of problems it solves and how they are structured. Its Aspects are
authored per role and are the same for every User. We deliberately do not
assemble an experiment from the Unknowns in a particular User's evidence.

The tempting alternative was to select Aspects per User so that each
experiment maximised new information. We rejected it. The product's promise is
a Playground where you experience a role as it actually is; an experiment
tuned to one User's gaps is a diagnostic instrument wearing a role's clothes,
and it would misrepresent the work. If the User already has analysis
experience, a consulting case still contains analysis, because consulting
does.

The mix we want arrives anyway, without engineering for it. Real roles contain
both familiar and unfamiliar work, so a fixed set of Aspects will overlap a
User's Confirmed Evidence in some places and not others. Where it overlaps we
can compute a Preference Shift; where it does not we get First Evidence. Both
feed the Direction.

Consequence: an Aspect that happens to match work the User asked for more of
is not evidence that we granted a request. Preference is recorded in Phase 2
and does not steer what an experiment contains.
